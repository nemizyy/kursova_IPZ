Ось детальний план того, що тобі потрібно зробити по бекенду згідно з ТЗ:

1. Проєктування бази даних (SQLite)
ТЗ вимагає використання SQLite для збереження даних. Тобі потрібно створити таблиці для:

Майна (Item): інвентарний номер (має бути унікальним), назва, категорія, вартість, дата додавання, статус (активне, списане, переміщене).

Історії операцій (History): запис усіх змін, переміщень або списань об'єктів.

2. Реалізація бізнес-логіки та валідації
Бекенд повинен строго контролювати правила обліку:

Перевіряти унікальність інвентарного номера при додаванні нового майна.

Валідувати зв'язки перед видаленням (щоб не видалити майно, яке пов'язане з активними процесами).

Автоматично оновлювати стан (статус) майна при його переміщенні або списанні.

3. Реалізація шаблонів проєктування (найважливіша частина)
У ТЗ чітко вказано 4 шаблони проєктування (GoF), які обов'язково треба реалізувати в коді:

Factory Method / Abstract Factory: Використовуй для створення різних типів майна (наприклад, FurnitureFactory для меблів, ElectronicsFactory для техніки). Це дозволить легко додавати нові категорії.

Strategy: Потрібен для алгоритмів фільтрації майна (наприклад, фільтрація за ціною PriceFilterStrategy або за датою DateFilterStrategy) та генерації звітів.

Observer: Використовуй для зв'язку між бекендом та фронтендом (Flet). Коли дані в базі змінюються (наприклад, додано нове майно), бекенд сповіщає GUI, щоб таблиця автоматично оновилася.

Command: Застосовуй для всіх операцій з майном (додавання, видалення, редагування). Це дозволить зберігати історію дій та легко реалізувати функцію скасування (Undo).
